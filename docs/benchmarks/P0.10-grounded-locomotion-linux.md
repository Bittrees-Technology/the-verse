# P0.10 hosted Linux grounded-locomotion baseline

**Measured:** 2026-08-27

This baseline measures the serialized P0.10 capsule-query and proof-scene physics cost on the hosted Linux release runner. It is an in-process distribution, not a production concurrency claim.

## Reproduction

Run each release probe serially. The benchmark binary also holds a process-wide lock so another invocation cannot accidentally overlap tests:

```bash
cargo test -p verse-physics --release --locked \
  --test compound_grid_benchmark -- \
  --ignored --nocapture --test-threads=1
```

The hosted job performs five consecutive invocations after building and smoke-testing the Linux package. Its package artifact contains the raw `P0.10-grounded-locomotion-linux.txt` output, machine description, native archive, and checksums.

## Results

Each row reports the median of the five run-level values.

| Measurement | Median result |
| --- | ---: |
| 2,048 static voxel colliders + one dynamic block, scene build | 1.267 ms |
| Same scene, one fixed step | 0.0042 ms |
| 2,816 static voxel colliders + 25-block dynamic grid, scene build | 1.922 ms |
| Same proof-budget scene, one fixed step | 0.0068 ms |
| Dirty 88-leaf chunk replacement, inner-sample median | 0.0308 ms |
| Dirty 88-leaf chunk replacement, inner-sample p95 | 0.0505 ms |
| Three-cast grounded set against 2,816 leaves | 0.0298 ms |
| One capsule cast within that set | 0.0099 ms |
| Exported Linux client + bundled server smoke | Passed |

The grounded set performs one support cast, one forward-obstruction cast, and one raised landing cast while ignoring the live character body. It represents the expensive P0.10 step-solver query path; ordinary supported frames do not always need all three casts.

## Interpretation

- One active grounded controller plus the proof scene is comfortably inside a 16.67 ms server frame on the hosted Linux runner.
- A naive linear extrapolation of the measured three-cast path is about 7.6 ms for 256 simultaneously stepping characters and 29.8 ms for 1,000. This is not a capacity result: broad-phase locality, scene density, persistence, replication, scheduling, and contention are absent from the probe.
- The 1,000-character extrapolation exceeds one 60 Hz frame. The thousands-of-players product requirement therefore depends on the accepted cell-partitioning, interest-management, active/sleeping-budget, and multi-process design; it cannot use one global physics scene with every character active.
- The P0.10 release evidence establishes functional cross-platform parity and a reproducible lower-level cost distribution. It does not establish P1 cell capacity or an end-to-end concurrency limit.
