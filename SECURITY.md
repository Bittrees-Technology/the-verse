# Security policy

The Verse is not yet accepting production security reports because no production software has been released.

Until a private disclosure channel is established:

- Do not publish wallet keys, credentials, personal data, or exploit instructions in an issue.
- Open a minimal GitHub issue requesting a private security contact without revealing the vulnerability.
- Do not test exploits against mainnet contracts or systems you do not own.
- Use local development networks and Sepolia for authorized testing.

Security-sensitive areas include:

- Inventory duplication and resource creation.
- Marketplace escrow and AMM accounting.
- Passkey and account recovery.
- Smart-account session permissions.
- Bridge and cross-chain reconciliation.
- Mod sandbox escape.
- Administrative creative mode.
- Safe and Security Council permissions.
- Server authority and client intent validation.
- Personal information and email handling.

A formal disclosure address, severity model, response targets, and bug-bounty policy must be adopted before public alpha.
